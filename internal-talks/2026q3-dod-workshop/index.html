從「做完」
到「真正做完」

我們到底在賣什麼——以及，每個任務怎麼講清楚驗收

2026-08　｜　Alfred Kang・CTK Pro

先講一件我最近一直在想的事

我們手上的案子
客戶其實自己也能弄個八九成了

甚至有客戶自己 Vibe Coding，把網頁上架了。

那……
他還需要我們嗎？

老實說——我用 AI 幫客戶的時候，
有些次也只是把他的話，轉手貼給 AI。

所以今天不是要檢討誰。是我自己先想清楚了，
想跟大家一起，把它變成一個每天做得到的動作。

回到最根本的問題

我們不是在寫 code。
也不是在做設計。

我們是幫客戶
把他想要的東西變出來

而「變出來」這件事——正在被 AI 接走。

所以我們的價值，要重新定義。這場就是在講：要定義成什麼。

先講一個人的故事

做出 Claude Code 的那個人
自己已經很少在寫 code 了

  • 他是誰Boris Cherny，Anthropic 的工程師——Claude Code 的創造者我們每天打開來用的那個工具，就是他帶頭做出來的。
  • 他現在做什麼他自己講：現在大部分時間不是在寫，是在看——AI 交出來的東西行不行哪裡該退回、哪裡要改、這樣能不能出去。

一個親手把這個工具做出來的人，最後把自己的位置，挪到了「驗收」那一端。

而這不只是他一個人的狀況

連寫 code 的人
現在主要的工作
都是「驗收」

產出量已經不是瓶頸了——「判斷這東西行不行」才是。
這句話，等一下還會回來兩次。

角色的界線，正在第二次模糊

終點是同一個：
把客戶要的變出來

第一次模糊 · 已經發生
前端 vs 後端
早就沒什麼意義了。誰碰得到、誰接得住，誰就做。
第二次模糊 · 正在發生
規劃 vs 執行
不管原本站在哪一邊，現在都往同一個地方走——想清楚要什麼，然後把它變出來。

那我們的價值，到底在哪

兩件事，AI 一個人做不到

  • 一我們懂得比客戶更深卡在哪一層？Cache 是什麼？是哪個細節把它卡住的？——客戶問不出來的問題，我們問得出來。這是我們當專家的舞台。
  • 二我們提得出他想不到的方案他要一扇門，我們看得出來他其實需要的是一條動線。

如果只是
他說一步、我們動一步——

那客戶當然會想：我直接跟 AI 講就好。

這不是威脅，是在告訴我們——力氣該花在哪裡。

留一個問題給我自己

如果我下的每一個指令，
都只是把客戶的話原封不動搬進去——
那這一整套流程裡，AI 跟我，差在哪裡？

這題我常問我自己。
接下來這段，就是我找到的那個答案。

A C T　4

那個位置
其實我們上一場已經講到門口了

Prompt · Context · Harness——今天只回收第三層。

三十秒回顧，不重講

三層，各自在管什麼

Prompt
提示詞
把意圖講清楚
→
Context
上下文
把脈絡餵對
→
Harness
調度／流程容器
指揮整組工具跑完一件事

上一場我說：Harness＝你是指揮家，不是演奏者。
今天要補上那句沒講完的——指揮家最後，一定要驗收。

這是今天最重要的一句

Harness 的天花板
不是你接了幾個工具
是它知不知道什麼叫做完

說不清「做完」，會發生什麼

它不會停在對的地方

說不清什麼叫做完 →它只能猜 →跑很久、看起來有做 →你還是要整份重看一次

沒有驗收條件，它跑再久也只是在賭；有驗收條件，它才收得起來。
這就是上一場說的——「中獎」跟「有把握」的差別。

那實際上要做什麼？

在你按下 Enter 之前
先把「做完」寫在最前面

不用裝什麼工具、不用學什麼指令。
就是幾句話，打在你那句需求的前面。

不是多一道手續——是把你原本事後才會發現的落差，提前到開工前發現。
那幾句話長什麼樣？等一下就寫給你看。

但也別走到另一個極端

把人拿掉的
全自動工廠——會失敗

無限堆 token、拿掉 code review，短期看起來很快，
但長期的可維護性補不回來。還是要規格先行、人守決策點。

而人要守的那個決策點——就是驗收。

出處：Dex Horthy〈Harness Engineering is not Enough〉（2026-07）

A C T　5

每個任務
先問一句：
什麼叫「真正做完」？

不是把眼前這一塊做完，就交出去。

「真正做完」的底線

三個不

  • 不把思考外包
  • 不把判斷外包
  • 不把煩惱丟回給客戶

這三件事外包出去，我們就退回成一根管子了。

前層 ｜ 先懂他為什麼要

當〔處境〕，
他想要〔動機〕，
好讓他能〔結果〕。

這叫 Job Story。我們面對的幾乎永遠是同一個客戶，
所以真正會變、也最值得問的，是「處境」。

後層 ｜ 再定義什麼叫做完

DOD 四問

1
要什麼
這次真正要達成的目標
2
怎樣算通過
驗收條件——照著做得完的步驟
3
不准動什麼
界線：哪些檔案／資料／流程不碰
4
做到哪停
停止條件：什麼情況要回來問人

剛剛說「打在最前面的那幾句話」——就是這四句。
第 2 題最容易寫壞：驗收要寫成「照著做得完」的步驟，不是丟一堆連結過去。

同一個任務，兩種寫法

差別長這樣

交辦時只講了這句
「把聯絡表單修一下，好了跟我說。」
    → 做的人只能猜；交出去之後，還是要有人整份重看一次。

    這份東西，寫一次可以用兩次

    同一份 DOD
    有兩個讀者

    讀者一
    你的同事
    他不用來回問你三次，就知道要做到哪、什麼時候該停下來找你。
    讀者二
    你的 agent
    它知道什麼叫通過，才收得起來——不然它只會一直跑，然後你整份重看。

    所以——你能把「做完」講到多清楚，就能把工作交出去多遠。

    現在，拿今天這個案子來練

    兩個人
    各寫一版 DOD

    STEP 1 · 2 min
    各自寫
    同一個任務，不討論，各寫一版：Job Story 一句 ＋ 四問。
    STEP 2 · 1 min
    攤開比
    兩版並排，先找不一樣的地方，不評分。
    STEP 3 · 1 min
    兜攏
    差異點當場記下來——那就是今天真正的產出。

    比的是兩版之間的差距，不是誰寫得比較好。
    兜不攏的地方，就是我們今天要對齊的地方。

    我們的驗收
    要對得起
    那個付錢的人心裡的「值得」

    站在窗口、帶案人的位置想一次：
    怎樣他會覺得，付我們這筆錢，比自己找 AI 值得。

    從下週起

    每個任務
    附一句 Job Story
    ＋ 一份 DOD

    不用寫得漂亮，先寫得出來就好。
    下次見面，我們來對——兩個人的「做完」，有沒有長一樣。

    你能把「做完」
    講到多清楚——
    就能把工作交出去多遠。

    交給同事，或交給 agent。是同一件事。

    謝謝

    從「做完」到「真正做完」——先講清楚，再交出去。
