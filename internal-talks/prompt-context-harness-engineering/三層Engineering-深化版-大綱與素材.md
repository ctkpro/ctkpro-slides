## 一、這份的一句話（切入點：你到底知不知道自己在跟 AI 說什麼？）

**「Opus 4.8 跟 4.6、GPT-5.6 跟 5.5、甚至 Fable，它們的差別到底在哪？大多數人答不上來——因為真正的問題不在模型，而在：當你在跟 AI 說話的時候，你真的知道自己在說什麼嗎？這一兩年變強的，到底是模型，還是你？」**

> 開場鉤子（給非新手的切入）：**「先問一個問題——不用回答我，也不用有壓力：Opus 4.8 跟 4.6 差在哪？GPT-5.6 跟 5.5 差在哪？Fable 又是什麼定位？……說真的，這題連每天在用的人都不一定講得清楚。而『答不出來』剛好就是今天的重點——因為真正決定你做得好不好的，根本不在這裡。所以換一個更重要的問題：跟一兩年前你在跟 ChatGPT、Claude 講話的時候比，變強的到底是模型，還是**你自己**？你現在到底知不知道，你在跟 AI 說什麼？今天這場，就是要把『你在跟 AI 說什麼』這件事，拆成三層、看清楚。」**

> 🎨 開場視覺建議：並排「Opus 4.8 vs 4.6 / GPT-5.6 vs 5.5 / Fable」幾個型號＋一個大問號，下一頁翻成「真正的問題 → 你知不知道自己在說什麼」。用「比模型」的好奇心當餌，一頁就轉進自省。

### 自我檢核：你是「有把握」，還是在「中獎」？（接開場）

> 把開場那個抽象問句，變成一個每個人都能對號入座的自我檢核。這頁不用聽眾回答，只要他心裡「咚」一下就成功了。

- 🎤「再具體一點。回想你這週跟 AI 的每一次對話——**你有多少次，是真的很清楚**：
>   - 你的**意圖**、你要的**結果**、你想**避開**的問題，都想清楚了？
>   - 你已經把**足夠的 context** 交代清楚了？
>   - 你清楚知道，這一次要**調用哪些工具、用什麼方式**去下這個命令？
>   - 你對這一次命令的**信心**，明確到你大概知道它會回來什麼樣子？
>
> 又有多少次，其實是——**你下了命令，但你也不知道它回來會變怎樣**？如果剛好做對了，那不是實力，是一種**感覺**、一種**『中獎』的感覺**。」
- 🔑 **這頁的鉤**：**「『有把握』和『中獎』的距離，就是你對 Prompt、Context、Harness 的掌握。今天，就是要把你從『中獎』帶到『有把握』。」**
- 🧭 **銜接下一段**：這正好接「錯覺」——**你之所以偶爾會中獎，是因為有東西在背後替你補洞**（模型＋Context）。但**中獎 ≠ 有把握**。
- 🎨 視覺建議：左欄「有把握」四個勾選項（意圖/結果、context、工具、信心），右欄一台「拉霸機🎰」——一句話對比「每次都有把握 vs 每次都在拉霸」。

## 二、為什麼要「深談」——先破一個錯覺

這份的價值，在於先破除一個聰明人也會有的錯覺：

> ❌ **錯覺**：「模型變強了，隨便下個 Prompt 事情就能搞定，Prompt 好像沒那麼重要了。」

這個錯覺**其實是真的觀察，但推錯了結論**。你之所以覺得「Prompt 隨便下也行」，是因為有兩股力量在**幫你補洞**：

1. **模型能力的提升**——模型自己會腦補、會糾錯，把你沒講清楚的部分猜對了一部分。
2. **Context 在背後被自動建立**——不管是你在對話介面裡累積的來回，還是你在整個專案裡留下的工作足跡（檔案、規範、歷史），系統把 Context 幫你補齊了。**這些 Context 彌補了你在 Prompt 上的缺乏**，才讓你產生「隨便下個 Prompt 就能搞定」的錯覺。

**但——補洞 ≠ 精準。** 靠模型腦補和 Context 補齊得到的結果，跟你「一開始就把意圖講清楚」得到的結果，在**掌握精準度上是有差別的**。錯覺讓你把「僥倖能用」當成「做得夠好」。

> 🎤「所以今天我不是要教你三個新名詞——你都會。我是要告訴你：**你以為 Prompt 不重要，是因為有兩個東西在替你擦屁股。今天我們把這層窗戶紙捅破，看清楚三層到底怎麼互相撐、互相拖。**」

## 三、【第一層】Prompt Engineering — 回歸第一性原理的根基

### 核心論點：Prompt 沒有退場，它退到「地基」

如果一路推回第一性原理，**Prompt 依然是「把事情做好」的最根本要件**。它不是被淘汰，是**沉到地基**——地基不會天天被人看見，但整棟樓能不能蓋好，全靠它。

### 心態轉變：不是寫更細，是把「意圖」講清楚

過去教 Prompt，是叫你寫得**更長、更細、更仔細**（角色、任務、格式、限制、一步步的步驟）。深化版要修正這個方向：

- ✅ **正確做法**：從另一個角度切入——
  - 給它一個**你想要的結果**；
  - 給它這件事的**來龍去脈**（背景、為什麼要做）；
  - 給它**最後產出該長什麼樣子**；
  - 但**你可能不會給它第一步、第二步、第三步的具體步驟**。
- 🔑 **把寫 Prompt 當成一種「能把意圖講得非常清楚」的能力**，而不是「把指令寫得非常細」的能力。

### 關鍵推論：一部分「寫 Prompt 的思考」會外移

當你把 Prompt 從「寫細節」升級成「表達意圖」，你會發現：**有一部分原本花在 Prompt 上的思考，會自然轉移到「設計背後的 Context」和「設計 Harness」的能力上**。這就是 Prompt Engineering 在心態上的轉變——**不是它變不重要，是它的一部分責任，往上長成了 Context 和 Harness。**

- 【Retro 案例】：同一個 code 生成需求，「一句話 prompt」vs「結果＋來龍去脈＋期望產出（但不寫死步驟）」的產出落差。
- **前沿佐證**（受眾非新手，可放）：
  - yt 2026-07-10（Simon Scrapes）：**「2026 年 prompt 建議反轉了」**——不再寫更長更細，改成「給結果＋context＋done 長什麼樣、別給步驟」，瓶頸從模型變成「你把意圖講清楚的能力」。**這條直接對應本層論點。**
  - yt 2026-07-03：大會 keynote「**Prompt is still a punch card**」——prompt 沒消失，是降為「打孔卡」級的底層原語。
  - yt 2026-07-10（IndyDevDan）：明確**反對**「prompt engineering 已死」——別被「AI 實驗室想讓你 token-max」的敘事帶走，要保住對 prompt 這個原語的控制。

- **一句記憶點**：🔑 **「Prompt 沒有變不重要，它變成了地基——你看不見它，但它撐著上面兩層。你以為隨便下也行，是因為模型和 Context 在替你補洞。」**

## 四、【第二層】Context Engineering — 對抗 Context Rot（脈絡腐化）

### 核心概念：Context Rot（脈絡腐化）——脈絡會「壞掉、變質」

第二層要帶出的關鍵詞是 **Context Rot（脈絡腐化）**。它會用兩種形式出現：

1. **累積型（漸進）**：當一個 Session 的 Token 累積到大約 **70%–80%** 之後，就開始出現 Rot——也就是**「掉記憶」**，模型會開始遺忘前面講過的事、前後不一致。
2. **壓縮型（必然）**：當你把整個 Session 的 Token（例如 1M 的 Context Window）**用滿**時，系統**必然**會做 **Compact（壓縮）**。而這個壓縮動作一旦發生，**100% 會掉東西**——不是「可能」，是「一定」。

### 為什麼 Context Engineering「高於」Prompt

在現階段的優化層級裡，**Context Engineering 其實排在 Prompt 之上**。原因：

- 在**長段的工作時間**裡，**Context 損失所帶來的影響，可能比「Prompt 沒下好」還嚴重**。一個沒下好的 prompt，你重下一次就好；但一段被 rot / compact 掉的 context，可能讓整條工作線的判斷基礎崩掉，而你甚至沒發現它已經忘了。

### 兩層環環相扣（本份的核心洞察之一）

Prompt 和 Context **不是各自獨立的**：

> **Prompt 沒下好 → 你的 Context 就死得更快、用得更快 → 更容易發生 Context Rot（脈絡腐化）。**

一個囉唆、失焦的 prompt，會讓模型消耗更多 token 去猜你的意圖、去繞路，於是你的 context window 被更快燒完，rot 和 compact 更早報到。**所以「把 Prompt 講精準」本身，就是在替 Context 省命。** 這就是為什麼第一層是地基——地基鬆，第二層垮得更快。

> **為什麼 Context 層長的是「判斷力」**（先埋、結尾回收）：管好 context 不是被動等它腐化，是一連串**主動取捨**——哪一段該留、哪一段該壓縮、哪一段該丟。你每做一次這種取捨，判斷力就練一次。所以到結尾那張「三個 Level」表，Context 對應的能力是「**取捨的判斷力**」。

- 【Retro 案例】：CLAUDE.md／專案脈絡文件／thinkr 記憶系統當「持久 context」；長 session 到 70–80% 主動 compact / 開新局的紀律。
- **前沿佐證**：
  - folo 2026-06-30-signal：Manus「若只能選一個指標，**KV-cache 命中率是 production agent 最重要**」；context 越積越差＝ **context rot（脈絡腐化）**。
  - folo 2026-07-02-signal：**RLM（遞迴壓縮）對抗 context rot（脈絡腐化）**——上下文越累積表現越差。
  - yt 2026-07-10：Claude Code 到 **70–80% 就開始 context rot（脈絡腐化）掉記憶**（autoCompact 屬底層衛生）；優化階梯裡 context 明確是「**prompt 之上、harness 之下**」的中間層。

- **一句記憶點**：🔑 **「Context 會腐化——累積到 70–80% 開始掉記憶，用滿必然壓縮、壓縮必然掉東西。長工作裡，管好 context 比下好一句 prompt 更值錢；而 prompt 沒下好，會讓 context 死得更快。」**

## 五、【第三層】Harness Engineering — 工具與流程的「指揮家」

### 核心概念：Harness 是一場「指揮」

Harness 不只是「你接了哪些工具」。它包含你手上**整套可調用的資源**：

- (a) 有哪些 **Agent** 可以幫你工作；
- (b) 有哪些 **Skills** 可以幫你工作；
- (c) 你已經串接好的 **MCP、API、CLI**。

真正的 Harness Engineering，是問一個更高階的問題：**在做一整件事的過程中，你該怎麼「規劃、調度」這些工具？**

### 指揮家的比喻（本層的主視覺）

你就像一個**指揮家在指揮樂團**——你必須決定**什麼東西該在什麼時候出來**。

> 就像聽一首歌：是**鼓聲先出來，還是吉他先進，還是人聲先唱？** 這整套「什麼工具、在什麼時序、以什麼力度出場」的調配，就是 Harness Engineering。

關鍵詞是 **「有意識地調用」**——不是手邊有什麼工具就抓什麼，而是**成系統地、有先後、有分工地**指揮這一整組工具跑完一件事。人退到指揮台上，守在「這一段該誰上、何時該回來問我」的決策點。

- 【Retro 案例】：一條實際的工作流——哪個 agent 先跑（規劃）、哪個 skill 接手（執行）、哪個 MCP/CLI 在哪一步出場、哪裡掛 autoreview、哪裡人工驗收。
- **前沿佐證**：
  - folo 2026-07-09-signal（Harrison Chase）：agent 產業已**從 framework 轉到 harness**——包在模型外那層（**記憶、工具、child agents、orchestration**）才是重點，不是 LLM 本身。
  - yt 2026-07-10：**Harness = 優化「包在模型外的系統」**（工作流編排、記憶、評估、權限）；被確立為新核心技能。
  - ⚠️ **反炒作（成熟訊號，值得對同事講）**：yt 2026-07-24（Dex Horthy「Harness Engineering is not Enough」）——「拿掉 code review、無限堆 token」的全自動工廠**會失敗**，因為「維持 codebase 長期可維護性是**訓練問題、harness 補不了**」。**指揮家再厲害，也取代不了『人守決策點＋規格先行』。**

- **一句記憶點**：🔑 **「Harness = 你是指揮家，不是演奏者。你決定哪個 agent / skill / 工具，在什麼時候、以什麼順序出場——有意識地調度整組工具跑完一件事。」**

## 六、收束：差距在哪裡？——你 vs 同行、你 vs AI

### 問題一：你會用 AI，你的同行也會用 AI——差距在哪？

AI 不是你的獨門武器。你會用，你的同行、對手、同事都會用；工具一樣、模型一樣。那**為什麼做出來的東西不一樣？** 差距不在「有沒有用 AI」，在「**用得多深**」。

### 問題二：那你跟 AI 之間呢？——AI 做得到什麼、你做得到什麼是 AI 做不到的？

再往前看一步：未來**你跟 AI 的差距**在哪？AI 會愈來愈能寫、能查、能執行——那還剩下什麼，是 **AI 做不到、只有你能做**的？

答案是三件事：**你的判斷力、你的決策、你意圖的清晰度。** 而這三樣不是天生的，也不是讀書讀來的——它們是**在一輪一輪的 Prompt、Context、Harness 裡，被磨出來、長出來的**：

- 每一次把 prompt 從「囉唆」逼成「精準的意圖」——你的**意圖清晰度**長一分；
- 每一次判斷「這段 context 該留、該壓、該丟」——你的**判斷力**長一分；
- 每一次決定「這一步交給哪個 agent、哪裡該我回來把關」——你的**決策力**長一分。

### 結論：差距，就是你對這三層的掌握度

所以，你跟同行的差距、你跟 AI 的差距，最後都收斂成同一件事——

> **你對 Prompt、Context、Harness 的掌握度。**

而現在每個人工作出來的品質差別，就攤在這三個 Level 上：

| Level | 它決定什麼 | 長出你哪個能力 |
|---|---|---|
| **① Prompt（提示詞）** | 你跟 AI 溝通的第一步。**你的 prompt 下得怎麼樣，決定了你的 context 多早就會腐化。** | 意圖的清晰度 |
| **② Context（上下文）** | 你對 context 掌握多少，**決定了你能多有效率地達成目標。** | 取捨的判斷力 |
| **③ Harness（治理／流程容器）** | 最外層。**你對整個工作流程有沒有一整套系統性的想法**——第一步幹嘛、第二步幹嘛、串什麼工具。 | 調度的決策力 |

- 🎤「回到開場那個問題——你到底知不知道自己在跟 AI 說什麼？今天之後，你有了一把尺：你『在跟 AI 說什麼』，就是在這三層上做選擇。而你在這三層上做的每一個選擇，都在長你的判斷、你的決策、你的意圖清晰度——**這些，才是 AI 到最後都替不掉你的東西。你也不再是每次下命令都在賭『這次會不會中獎』，而是愈來愈多次，你一開口就有把握。**」

### 最後一問（鏡子·倒數第二頁）

> **設計意圖**：這是全場的最後一擊，但**刻意用「鏡子」不用「判決」**——不說「你會被取代」，改問「AI 跟你差在哪」，讓聽眾自己推出那個結論（衝擊更深、但不傷關係）。打的是「搬運」這個**行為**、不是「人」；講者先把自己也放進來（「我也常問我自己」）；然後立刻把三層接成出口。**講完這頁翻下一頁的賦能金句收尾，別停在這頁的重量上。**

- 🎤「最後，留一個問題給你自己，不用回答我——
> **如果你下的每一個 prompt、餵的每一段 context、搭的每一套 harness，都只是把客戶的話原封不動搬進去……那這一整套流程裡，AI 跟你，差在哪裡？**
> 這題，我也常問我自己。而今天講的這三層，就是那個『差在哪裡』的答案——它是你從『搬運』，長到『判斷』的那條路。」
- 🔑 **一句記憶點**：**「別當一個把需求原封不動搬進 AI 的搬運工——你和 AI 的差別，就長在你多放進去的那一點判斷裡。」**
- ⚠️ 講者提醒：這頁對**內部同事**用，力道剛好（鏡子式、不點名）；若哪天對更熟、更需要震撼的場，可換更直白的版本（「那遲早被取代的就是你」），但**內部首選這版**，避免恐懼傷信任。

- **一句收尾金句（擇一 · 真正的最後一頁，賦能收）**：
  - 🏆 **「你跟同行的差距、你跟 AI 的差距，其實是同一個差距——你對 Prompt、Context、Harness 的掌握度。」**
  - 🏆 **「AI 能做的愈來愈多，但你的判斷、決策、意圖清晰度做不了假——它們是在一輪輪 Prompt、Context、Harness 裡長出來的。」**
  - 🏆 **「別問哪顆模型強，問你自己：你知不知道，你在跟 AI 說什麼？」**

## 七、三層關係總表（深化版 · 帶因果）

| | **① Prompt** | **② Context** | **③ Harness** |
|---|---|---|---|
| **本質** | 回歸第一性原理的**地基** | 對抗 **Context Rot（脈絡腐化）** 的脈絡管理 | 工具與流程的**指揮調度** |
| **它決定什麼** | context 多早腐化 | 達成目標的效率 | 整個工作流有沒有系統 |
| **深化重點** | 不寫更細，而是**把意圖講清楚**（給結果＋來龍去脈＋產出樣貌，不給步驟） | **70–80% 開始掉記憶；用滿必然 compact、必然掉東西**；長工作裡比 prompt 更關鍵 | **像指揮樂團**——哪個 agent/skill/MCP，在什麼時序出場；有意識地調用 |
| **與其他層的耦合** | prompt 沒下好 → context 死更快 → 更易 Context Rot（脈絡腐化） | context 是 prompt 之上、harness 之下的中間層 | harness 也非萬能——仍要**規格先行、人守決策點** |
| **前沿出處** | yt 7/10（prompt 建議反轉）、yt 7/03（punch card） | folo 6/30・7/02（context rot / KV-cache / RLM）、yt 7/10 | folo 7/09（framework→harness）、yt 7/10、yt 7/24（is not enough） |

## 八、講者提醒 & 待補

- **這份對「非新手」**：可以放 context rot、KV-cache、compact、harness=orchestration 這些詞，不用像 07-24 版那樣全程比喻。
- **實例走「討論時自然帶入」**：三層的 ctkpro 真實案例**不預填進草稿**——現場討論／實際帶同事時，依當下情境舉例最貼。草稿只負責把觀念與因果講清楚。
- **兩個核心洞察別漏講**（這是深化版跟入門版的差異點）：
  1. **「Prompt 不重要」是錯覺**——因為模型腦補＋Context 自動補洞（兩個成因要講清楚）。
  2. **三層環環相扣**——prompt 沒下好會讓 context 死更快；harness 再強也要人守決策點。
- **模型那段的分寸（開場）**：型號比較（Opus 4.8 vs 4.6、GPT-5.6 vs 5.5、Fable）只是**鉤子**——目的是用「比模型」的好奇心，把聽眾一頁就引到「**你到底知不知道自己在跟 AI 說什麼**」這個自省。拋完就轉，別真的陷進「那到底該用哪顆」。
- **收尾的分寸（結尾）**：結尾不談「趨勢／這季功課」，談**差距**——你 vs 同行、你 vs AI。核心句是「判斷力、決策、意圖清晰度，是在一輪輪 Prompt/Context/Harness 裡長出來的，而這正是 AI 替不掉你的」。開場的自省問句要在結尾**回收**（首尾呼應）。
- **與 07-24 版的關係**：07-24 是入門階梯（對外/新手），這份是深化因果（對內/非新手）。**同一套 Prompt→Context→Harness 骨架，兩個深度**。之後做投影片時可決定：對 Aron/Wei 用這份、對 BNI 用 07-24 版。
- **下一步**：這份是論述草稿，觀念對齊後再談投影片（HTML）怎麼做——尤其「指揮家/樂團」這個比喻很適合做成一頁主視覺（工具在不同時間點進場的時序圖）。
