# 給設計公司的價值主張——投影片製作計畫

本文件規劃 `for-design-company` 這份對外簡報的頁面結構。素材與論述依據見同資料夾的 [價值主張-深化研究.md](價值主張-深化研究.md)（v2）。

## 目標定位

> CTK Pro 是設計公司的**落地夥伴**——你負責讓它好看，我們負責讓它上得去、活得久。

這份簡報的對象與 `ctkpro-intro`（給終端企業客戶）**完全不同**，不可沿用：

| | `ctkpro-intro` | **本簡報** |
|---|---|---|
| 對象 | 終端企業客戶 | **設計公司／廣告 agency** |
| 賣什麼 | 網站建置與維運 | **賣「漂亮網站」的落地能力**（不賣 DMZ） |
| 關係 | 甲方 ↔ 乙方 | **同業合作／轉介夥伴** |
| 成功定義 | 成交一個案子 | **建立長期轉介關係** |

對應 [打法②](../../../thinkr/3_works/a-既有優化/ctkpro/藍圖/2-指導方針.md)：H2 目標為活躍轉介夥伴 ≥5 家。

### 三個必須建立的印象

1. **我們懂你的專業，不會來搶你的活**（設計歸你）。
2. **我們解決你交付路上真正卡住的三道牆**（上線、客戶 IT、無障礙）。
3. **我們會保護你**（不接走客戶、責任分擔）。

## 敘事主軸：三道牆

整份簡報用一條敘事線貫穿——**設計做完之後，還有三道牆**：

```
設計完成 → 🧱牆①：做得出來，但推不上去
         → 🧱牆②：客戶的資訊部門那一關
         → 🧱牆③：無障礙合規
         → CTK Pro 補的就是這三道牆
```

### ⚠️ 開場的紅線（重要）

- **不要說「AI 讓你們產能變多」**——好設計不是靠量拼出來的，這樣講預設對方在拼量，可能冒犯專業。
- **不要斷言對方用 AI 用得多深**——各家程度差異極大、無法預測。
- **要主動承認他們的能力**：「我們知道，畫面你們自己做得出來，而且做得很好。」先卸防備，再帶出斷點。
- **不要主打「100% 精準還原設計稿」**——現在 AI 寫 code 處理 RWD／hover／focus／disabled 又快又好，這句話已無競爭力，還會顯得不了解對方現況。

## 設計方向

沿用本 repo 既有風格與骨架：

- 以 `bids/yilan-bids/index.html` 的 1280×720 `#stage` 架構為骨架，保留頁碼、進度條、左右 1/6 點擊翻頁、鍵盤翻頁、全螢幕。
- 白／淺底、投影機友善（本簡報多為**到對方辦公室簡報**，可能用會議室螢幕或投影機，維持淺底最穩）。
- **加入 4:3 safe area**。
- 每頁只放一個主要訊息。

### 色彩

沿用 `ctkpro-intro` 的 CTK Pro 品牌色系（`--brand:#e11f27`），保持對外簡報一致性。

⚠️ **本簡報有較多數據頁**（WebAIM、資安實證、審查清單），需要**第二色相**做圖表區隔——建議加 `--teal:#0E7490`（與紅色區隔明確，白字達 AA）。原則沿用 CLAUDE.md：每條色帶文字統一白色。

紅色只作重點、頁碼、章節標記與 CTA，不大面積鋪滿。

## 頁面大綱（共 14 頁）

### 1. 封面

主標：

> 設計歸你，落地歸我們

副標：

> CTK Pro 竑盛科技 ｜ 設計公司的網站落地夥伴

目的：一句話定義關係——**合作，不是競爭**。

---

### 2. 開場：我們知道，畫面你們自己做得出來

核心訊息：

> Figma Make、Lovable、v0、Framer——這些工具你們已經在用，而且用得很好。
> RWD、hover、focus、disabled，AI 寫 code 處理得又快又好。

目的：**主動卸下對方防備**。這頁是整份簡報成敗的關鍵——如果一開口就講「我們還原度很高」，對方會立刻覺得我們不懂現況。

> 💬 講稿方向：「所以今天我不是來跟你說我們畫面做得比較好。我想談的是——**畫面做完之後的那一段。**」

---

### 3. Index：設計完成之後，還有三道牆

目錄（同時就是敘事骨架）：

- 🧱 牆①　做得出來，但推不上去
- 🧱 牆②　客戶的資訊部門
- 🧱 牆③　無障礙，而且它在變壞
- 　　　我們補的三件事
- 　　　我們怎麼保護你

目的：讓對方知道簡報怎麼展開，並預告「這三件事你可能都遇過」。

---

### 4. 🧱 牆①：做得出來 ≠ 上得去

核心訊息：

> Figma Make 給你的不是 production code，是**一份可以跑的原型**。
> 這兩件事之間，隔著一個工程團隊。

可用的硬證據（見研究檔 2.2）：

- 匯出常**缺關鍵專案檔**：`package.json`、`tailwind.config.js`、`tsconfig.json`、`vite.config.ts` → 本地重建、修改、除錯極度困難。
- **第二次提示修改後，專案可能變成無法建置**。
- **沒有回流 Figma Design 的完整路徑**，只能存本機副本或下載 code。
- 業界評測共識：單檔化、結構鬆散、缺測試、缺本地開發環境。

版面建議：左側放「你以為拿到的」（一份完整專案）、右側放「實際拿到的」（缺檔案的資料夾示意）。

> ⚠️ **誠實原則**：同頁或下一頁要主動承認——**小型形象站用 Framer 這類平台自動處理網域與 SSL，確實不需要我們**。講出這點反而建立可信度。

---

### 5. 牆①的另一邊：從「做畫面」變成「做整合」

核心訊息：

> 一旦客戶要求放自己的主機、或接既有系統，工作性質就變了。

建議用表格呈現（左：工作項／右：為什麼需要工程背景）：

| 工作項 | 需要什麼 |
|---|---|
| 拆成可維護元件 | 架構能力 |
| 接客戶 API、CMS 欄位、表單後端 | CMS schema、後端整合 |
| SEO：title/OG/canonical/結構化資料/語系 | 索引機制 |
| 追蹤碼與事件規格（GA/GTM/像素） | 版本控管（重新生成就失效） |
| 多語系路由 | 路由架構 |
| CI/CD、staging、rollback | build pipeline |
| DNS、SSL、環境變數、SSR/SPA | 純工程知識 |

> 💬 講稿方向：「這些不是設計問題，是工程問題。**不是你們做不到，是這本來就不該是你們的事。**」

---

### 6. 我們還原的，是設計意圖（上）：意圖的「延伸」

核心訊息：

> 設計稿定義的是**理想狀態**。網站上線後，99% 的時間都不在理想狀態。

四個提問（設計稿上沒畫、但上線後一定會遇到）：

- 客戶把文案從 8 個字改成 40 個字，版面怎麼撐？
- 商品只有 1 筆、或有 200 筆時，列表長什麼樣？
- 圖片沒上傳、API 掛掉、搜尋沒結果——**空狀態與錯誤狀態**呢？
- 客戶自己進 CMS 改內容後，**設計還守得住嗎？**

> 💬 收句：「這些 AI 會自己猜，猜的依據是訓練資料的慣例，**不是你的設計意圖**。而猜錯的鍋，是你在背。」

版面建議：四格提問卡，每格一句，留白要夠。

---

### 7. 我們還原的，是設計意圖（下）：意圖的「存續」

核心訊息：

> 你花三個月做的設計，值得撐三年，而不是三個月。

論述：

- 網站交付後會經歷：客戶自己改內容、加活動頁、換 banner、外掛更新、瀏覽器改版。
- **多數網站在上線 18 個月後，已經不是設計師交出去的那個樣子了。**

> 💬 **本頁金句（建議做成大字頁）**：「我們維護的不只是網站，**是你的作品集。**」

目的：這句對設計公司有特殊份量——他們的作品要拿去比稿、拿獎、放官網。網站爛掉，爛的是他們的招牌。同時這條天然連到長期維護合約（MRR）。

---

### 8. 🧱 牆②：客戶的資訊部門

核心情境圖（本頁主視覺）：

```
大企業行銷部門 ──委託──▶ 設計公司 ──交付──▶ ❌ 卡在客戶的資訊/IT 部門
（要品牌、要速度、要如期上線）              （要合規、要稽核、要有人負責）
```

核心訊息：

> 你的窗口是行銷部門，講品牌、講創意，頻率相合。
> 但案子要上線，得過一群你完全不熟、也講不贏的人。

> 💬 **本頁金句**：「你搞得定行銷部門的美感，但**搞不定他們資訊部門的問卷**。那份問卷，我們天天在填。」

補一句關鍵：**這關卡住通常不是設計公司的失誤，卻會算在他們頭上**——專案延宕、活動開天窗、客戶不滿意。

---

### 9. 資訊部門到底會問什麼

核心訊息：

> 大企業的廠商審查不是只看一張證照，是看**整套證據鏈**。

清單（做成表格，這頁本身就是殺傷力）：

| 類別 | 要求 |
|---|---|
| 制度證明 | **ISO 27001 證書**、SOC 2 Type II |
| 資安問卷 | SIG、CAIQ 或客製問卷 |
| 測試報告 | 滲透測試報告（含修補證明）、弱點掃描／SAST／DAST |
| 個資 | 個資處理契約（DPA）、資料流向圖、子處理者清單 |
| 營運 | 事件通報與 SLA、存取控管與 MFA、備份／復原／刪除機制 |

> 🎯 設計時**把 CTK Pro 已具備的項目打勾標示**（ISO 27001、iPAS 資安工程師）——讓對方一眼看到「這些我一個都答不出來，但他們可以」。

---

### 10. 為什麼資訊部門現在比以前更嚴

核心數據（本頁只放這一個數字，做大）：

> **第三方涉入的資料外洩：15% → 30%**
> —— Verizon DBIR 2025

論述：**資訊部門不是在刁難，是他們自己的風險真的變高了。**

接著補 AI 生成網站的資安實證（小字表格或第二欄）：

| 實證 | 數字 |
|---|---|
| Tenzai 測 5 大 vibe coding 平台的 15 個應用 | **69 個漏洞**，約半數 high/critical；**全部**缺 CSRF、**所有工具**引入 SSRF |
| CVE-2025-48757（Lovable + Supabase RLS） | 170+ 專案、303 端點外洩 email、電話、付款狀態、API key |
| Escape.tech 掃 5,600 個 vibe-coded 應用 | 2,000+ 漏洞、400+ secrets、175 起 PII 外洩 |
| CMU SusVibes 研究 | **61% 功能正確，只有 10.5% 通過安全審查** |
| Veracode 2025 | AI 生成碼在 **45%** 任務中引入漏洞 |

> 💬 **金句**：「功能正確 61%，安全過關只有 10.5%。**你客戶的資訊部門，看的正是那 10.5%。**」

---

### 11. 🧱 牆③：無障礙，而且它正在變壞

核心數據（WebAIM Million 2026，做成對比表）：

| 指標 | 2026 | 2025 |
|---|---:|---:|
| 首頁有 WCAG failure | **95.9%** | 94.8% |
| 每頁平均錯誤數 | **56.1** | 51.0 |
| 低對比文字 | **83.9%** | 79.1% |
| 表單欄位缺標籤 | 51.0% | — |
| 跳過標題層級 | 41.8% | 39% |

> 💬 **金句**：「無障礙不是在變好，是在變壞——**六年來的改善趨勢在 2026 反轉了**。而且六大常見錯誤佔所有錯誤的約 96%：**少數幾個設計系統決策，被複製了幾百萬次。**」

⚠️ 同頁帶出「約 2/3 的無障礙問題在設計階段就決定」（顏色對比、字級、focus、標題階層、表單標籤）——**這正是設計師手上的東西**，所以這是「我們一起解決」，不是「你們做錯了」。

> ⚠️ **措辭紅線**：這頁很容易講成指責設計公司。務必框成**「這是設計與開發之間的斷層，不是誰的錯」**。

---

### 12. 而且客戶開始「非做不可」了

核心訊息：無障礙有法規當引擎，不是加分項。

| 對象 | 強制程度 |
|---|---|
| 政府機關、附屬機構、**學校** | **法定**（身權法 52-2） |
| 政府/學校新設或改版 | 原則上 **AA** |
| 銀行、保險、證券 | **準強制**（金融友善服務準則） |
| **政府採購** | 可把 **AA＋標章寫成契約義務** → 不符可**驗收不合格、減價、違約** |
| 跨境電商／SaaS | **歐盟 EAA**（2025/6/28 起，看有無對歐盟消費者提供服務，非公司設立地） |
| 一般民企 | 無強制，但已有 **345 家**取得標章（35 家 AAA），數發部與 **ESG** 連結 |

標章實務（小欄位）：

> 申請與檢測**免費**，效期 **3 年**，滿半年可被抽測，年抽測率 **5%**。
> 「標章免費，難的是**做到能過**，以及**三年內不被撤銷**。」

⚠️ 製作時注意：現行規範為**「網站無障礙規範（110.07）」**，舊稱「2.0 版」**已不再受理**；ADA Title II 期限已**延後至 2027/4/26**（若要提必須用更新後日期）。

### 14. ⭐ 我們怎麼保護你

**這頁可能比任何技術頁都更能促成合作。**

設計公司轉案給我們，最怕的三件事（見研究檔第五章）：

1. **我們跑去接走他的客戶**
2. 我們做爛了，**客戶怪到他頭上**
3. 上線後出事，**他被牽連**

本頁要正面回答（🔬 **具體承諾內容待 Alfred 拍板**）：

- **不繞過你直接接觸客戶**的承諾（是否書面化？）
- 交付掛名方式：以你的名義？共同掛名？
- 責任怎麼分、出事誰出面
- 客戶關係歸屬的界線

> ⚠️ 這頁的內容**不能由我擬定**——涉及商業承諾與合約界線，必須 Alfred 決定尺度。先做版型、內容留空。

## 內容原則

### 不可臆造

- **案例**：若要放實際案例，只放**已確認可公開**的內容。目前研究檔未確認 CTK Pro 做過幾個無障礙標章案 → **第 11-13 頁若要放案例，需先向 Alfred 確認**。
- **數字**：無障礙／SEO／效能**缺乏公開量化研究**（資安有）。這三項只講機制與案例，**不要編數字**。
- **查不到、不要用**：企業把 ISO 27001 當供應商門檻的比例、網站專案被 IT 擋下比例、shadow IT 占比、台灣個資法 2025-26 修法進展——**全部查無可靠來源，簡報不得出現**。

### 語氣

- 全程站在**「同業合作」**而非「廠商推銷」的位置。
- 講設計公司的不足時，一律框成**「這本來就不該是你的事」**，不是「你們做不好」。
- 主動承認我們不做／不搶的部分，反而建立可信度。

## 待確認事項（需 Alfred 拍板）

1. **第 14 頁的保護承諾尺度**——不接觸客戶是否書面化？掛名方式？責任分擔？
2. **CTK Pro 實際做過幾個無障礙標章案**——決定第 11-13 頁能不能放案例，也影響整包主張的強度。
